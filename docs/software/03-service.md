# Tablo — софт: сервис (§6)

> Часть проекта софта, индекс — [`tablo-software.md`](../../tablo-software.md). Номера §N сквозные по всем частям.

## 6. Сервис

### 6.1 Стек

- **Python 3.12, один процесс asyncio.**
- `aiohttp` — веб-сервер, WebSocket к плате, HTTP-клиент, WebSocket к HA. Одна библиотека на всё, чтобы не тянуть FastAPI + uvicorn + httpx.
- `Pillow` — вёрстка, без браузера.
- `icalendar`, `openpyxl`, `selectolax` (HTML t.me), `segno` (QR), стандартный `imaplib` в отдельном потоке.
- `anthropic` — подгружается лениво, только на время запроса.
- **SQLite** (`data/tablo.db`) — снимки оценок, кэш разметки таблиц, словарь переводов, просмотренные посты и письма, текущие новости и дедлайны.

### 6.2 Внутреннее устройство

```
источники ──▶ хранилище (SQLite + память) ──▶ модель экрана ──▶ рендер (Pillow) ──▶ кадр ──▶ плата
   ▲ расписание каждого                         (чистые данные)    1 бит, CRC
   └ события HA (мгновенно)
```

- **Источники** — независимые модули с интерфейсом «забери данные, верни типизированные записи». У каждого своё расписание, кэш и флаг «последний раз успешно». Ошибка одного не ломает остальные: блок показывает последние известные данные.
- **Модель экрана** — чистые данные без пикселей: «3 дедлайна», «прогноз на 8 часов», «плитка 3 включена». Её можно сравнивать и тестировать.
- **Рендер** превращает модель в картинку. Раскладка — координаты в одном файле.
- Изменилась модель → через 2 с рендер → если CRC другой, кадр уходит на плату.

### 6.3 Вёрстка

- Inter в чистом ч/б: сравним `fontmode="1"` и рендер в оттенках серого с порогом. Сначала на превью, окончательно — на живой панели.
- Текст, который не помещается, обрезается с «…».
- Значки погоды — свои, одной линией, как в макете: солнце, луна, облако, облако с 1–3 штрихами, снег, гроза, туман.
- **Значки кнопок — Material Design Icons** из файла шрифта MDI. Имя `mdi:lamp` переводится в символ шрифта по `meta.json`, размер 32 px. Это те же имена, что в HA.
- Срочный дедлайн выделен инверсией.

### 6.4 HTTP API

Для интеграции HA и отладки, на том же порту 8765. Запросы, меняющие состояние, а также `GET /api/config` и `GET /api/deadlines`, требуют `Authorization: Bearer <api_token>`.

| Метод и путь | Что делает |
|---|---|
| `GET /api/config` | Текущий конфиг без секретов: интеграция берёт его при подключении (§8.1) |
| `PUT /api/config` | Интеграция присылает полный конфиг (§8) |
| `GET /api/deadlines` | Дедлайны для списков дел: `uid`, `title`, `due`, `category`, `source`, `overdue` (§8.4) |
| `POST /api/deadlines` | Свой дедлайн: `{title, due, category}` |
| `PATCH /api/deadlines/{uid}` | `{done: true}` скрывает; `{title, due}` меняет (дедлайн из источника скрывается, остаётся своя копия) |
| `DELETE /api/deadlines/{uid}` | Свой удаляется, из источника скрывается |
| `POST /api/overlay/qr` | `{networks: [...], duration_s}` |
| `POST /api/overlay/message` | `{title, text, icon, duration_s}` |
| `POST /api/refresh` | `{full: bool, refetch: bool, sources: [...]}`: `refetch` опрашивает источники сейчас (`grades`, `hseapp`, `ical`, `news`, `weather`; без `sources` — все) |
| `GET /api/status` | Состояние платы, источников, HA |
| `GET /frame.png` | Текущий кадр картинкой |
| `GET /emu` | Эмулятор (§9) |

### 6.5 Конфигурация

- **Секреты** — в `.env` сервиса: токен HA, ключ Anthropic, пароль приложения Яндекса, токены платы и API.
- **Содержательные настройки** (кнопки, ссылки, каналы, сроки) — в HA. Интеграция присылает их через `PUT /api/config`.
- Сервис хранит последний полученный конфиг на диске и работает по нему, даже если HA недоступен.
- Пока интеграции нет (этапы 1–6), тот же конфиг читается из `config.yaml`. Схема одна и та же.
