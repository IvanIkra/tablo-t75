## 1. Состав системы

```
 Open-Meteo ───┐
 iCal РУЗ ─────┤
 Google Sheets ┤                                   WebSocket :8765
 t.me/s/… ─────┼──▶  Сервис Tablo  ◀══════════════════════════▶  Плата ESP32-L
 Яндекс IMAP ──┤    (Python, Pillow,    кадры 1 бит, конфиг ▶     или эмулятор
 the university app ────┤     SQLite)            ◀ нажатия, статус        в браузере
 Claude Haiku ─┘        ▲   │
          HTTP API      │   │  HA WebSocket API
       (конфиг, экраны) │   ▼  (состояния, call_service, события)
                  Home Assistant + интеграция «Tablo»
```

| Часть | Что делает | Где живёт |
|---|---|---|
| **Сервис** | Собирает данные, вёрстает кадр, держит соединение с платой, выполняет действия кнопок в HA | Docker на `server` |
| **Эмулятор** | Ведёт себя в точности как плата, по тому же протоколу | Веб-страница, которую отдаёт сервис, работает в браузере на Маке |
| **Интеграция HA** | Интерфейс настройки, триггеры кнопок для автоматизаций, действия `tablo.*` | `custom_components/tablo` в конфиге HA |
| **Прошивка** | Выводит кадры, рисует часы, дату и строку статуса, опрашивает кнопки | ESP32-L |

Главный принцип не меняется: умный сервер и простое устройство. Плата не знает, что на картинке, но умеет жить без сервиса: часы идут, строка статуса честно показывает сбой.

## 2. Кто что рисует

Экран 800×480, 1 бит. Координаты — `x, y, ширина, высота` в пикселях. Окончательно уточним при вёрстке; прошивка получает зоны в сообщении `config` (§3.3), поэтому их можно менять без перепрошивки.

| Зона | Прямоугольник | Рисует | Содержимое |
|---|---|---|---|
| Часы и дата | `0, 0, 184, 100` | **прошивка** | Время 64 px, ниже «Wed, Oct 14 · wk 7» |
| Строка статуса | `600, 0, 200, 24` | **прошивка** | Wi-Fi, облако (сервис), домик (HA), «synced HH:MM» или чёрная плашка «offline since HH:MM» |
| Погода сейчас | `188, 14, 142, 68` | сервис | Значок, температура, «feels» |
| Прогноз | `340, 26, 452, 68` | сервис | 8 колонок: час, значок, температура |
| Deadlines | `0, 100, 272, 164` | сервис | |
| Grades | `0, 264, 272, 164` | сервис | |
| News | `272, 100, 288, 328` | сервис | |
| Classes | `560, 100, 240, 164` | сервис | |
| Home | `560, 264, 240, 164` | сервис | |
| Кнопки | `0, 428, 800, 52` | сервис, плата инвертирует | 8 плиток по 100×52 |

- Сервис оставляет зоны прошивки **белыми**. Плата рисует их поверх кадра.
- **Дата на плате:** «Wed, Oct 14» плата берёт из своих часов, номер недели «wk N» считает сама от `semester_start` из конфига. Поэтому дата сменится в полночь, даже если сервис лежит.
- **Плитки кнопок:** залитая плитка — «включено». Значки и заливку рисует сервис. При нажатии плата **сразу** инвертирует плитку (§4.2).
- Шрифт — Inter. Интерфейс экрана на английском.

## 3. Протокол плата ↔ сервис

### 3.1 Соединение

- Одно WebSocket-соединение: `ws://<сервис>:8765/ws?device=<id>&token=<токен>`. Токен в query, а не в заголовке, потому что браузерный эмулятор не умеет ставить заголовки на WebSocket.
- Текстовые сообщения — JSON с полем `type`. Бинарные сообщения — только кадры (§3.2).
- Пинг на уровне WebSocket каждые 20 с. Нет трафика 60 с — соединение считается мёртвым.
- Переподключение с паузами 1, 2, 4, 8, 16, 30, 30… с.
- При подключении плата шлёт `hello` с CRC последнего кадра. Сервис отвечает `config`, `health` и, если CRC не совпал, текущим кадром.

### 3.2 Кадр (бинарное сообщение)

| Смещение | Размер | Поле | Значение |
|---|---|---|---|
| 0 | 4 | magic | `TBLF` |
| 4 | 1 | version | `1` |
| 5 | 1 | kind | `0` — основной кадр, `1` — полноэкранный (§5) |
| 6 | 2 | ttl_s | Для полноэкранного: сколько секунд показывать (LE u16), иначе 0 |
| 8 | 4 | frame_id | Монотонный номер кадра (LE u32) |
| 12 | 4 | crc32 | CRC32 полезной нагрузки |
| 16 | 2 | width | 800 |
| 18 | 2 | height | 480 |
| 20 | 48 000 | payload | Строки сверху вниз, 100 байт на строку, старший бит — левый пиксель, **1 = чёрный** |

- Без сжатия: 48 КБ по локальной сети — это доли секунды.
- Плата хранит последний основной кадр, сравнивает новый со старым построчно и делает **частичное обновление** только прямоугольника, в котором есть изменения.
- Если контроллеру экрана нужна обратная полярность, прошивка инвертирует при выводе. Протокол не меняется.
- Сервис шлёт новый кадр, только если CRC изменился, и не чаще раза в 2 с. Исключение — кадр в ответ на кнопку.

### 3.3 Сообщения

**Плата → сервис**

| type | Поля | Когда |
|---|---|---|
| `hello` | `fw`, `device`, `last_crc`, `rssi`, `uptime_s` | После подключения |
| `button` | `id` 1–8, `press` `short` / `long`, `seq`, `local` (для 8) | Нажатие. Кнопка 8 тоже отправляется, но как событие: действие у неё прошито |
| `overlay_closed` | `reason`: `button` / `ttl` | Закрыт полноэкранный экран |
| `status` | `rssi`, `uptime_s`, `heap`, `partials_since_full`, `ip` | Раз в 60 с |
| `frame_ack` | `frame_id` | Кадр выведен |

**Сервис → плата**

| type | Поля | Когда |
|---|---|---|
| `config` | `tz` (`MSK-3`), `ntp`, `semester_start`, `zones` (§2), `long_press_ms` (600), `full_refresh` (`at: "04:00"`, `max_partials`), `offline_after_s` (120), `diag_ttl_s` (30) | После `hello` и при изменении настроек |
| `health` | `ha` (bool), `synced_at` (`HH:MM`) | Раз в 60 с и при изменении |
| `button_result` | `seq`, `ok`, `error` | Действие выполнено или провалилось (§4.2) |
| `full_refresh` | — | Принудительное полное обновление (действие HA) |

### 3.4 Обновление экрана

- **Частичное** (≈0,3 с): изменения кадра, часы раз в минуту, плитки кнопок.
- **Полное** (≈3 с, с миганием): ежедневно в `full_refresh.at` (по умолчанию 04:00), после `max_partials` частичных подряд, по кнопке 8 и по команде `full_refresh`. Значения подберём на живой панели по остаточным следам.

## 4. Кнопки

### 4.1 Раскладка

| Кнопка | Короткое | Долгое (≥ 600 мс) | Настраивается |
|---|---|---|---|
| 1–7 | Действие из HA | Своё действие из HA | **В HA** (§8.2) |
| 8 | Полное обновление и запрос свежего кадра | Экран диагностики на 30 с | Прошито |

- Когда порог долгого нажатия пройден, плата сразу меняет вид плитки (рамка вместо заливки), чтобы было понятно, что засчиталось долгое, ещё до отпускания.
- Подавление дребезга — 20 мс.

### 4.2 Мгновенный отклик

1. Нажатие → плата **сразу** инвертирует плитку поверх основного кадра (локальная пометка) и шлёт `button`.
2. Сервис выполняет действие в HA и ждёт `state_changed` нужной сущности. Таймаут — 10 с: облачный Tuya бывает медленным.
3. Успех → сервис шлёт новый основной кадр с настоящим состоянием плитки, потом `button_result ok`.
4. Плата по `button_result` (или через 12 с без ответа) снимает локальную пометку и перерисовывает плитку из основного кадра. Если команда не прошла, плитка возвращается в прежний вид.
5. Сервис недоступен → плата инвертирует плитку и через 1,5 с возвращает обратно: видно, что нажатие не ушло.

## 5. Полноэкранные экраны

Кадр с `kind = 1` показывается на весь экран. Плата не рисует поверх него часы, статус и плитки.

- Через `ttl_s` плата **сама** возвращает основной кадр. Поэтому экран не зависнет, даже если сервис упадёт посреди показа.
- Пришёл новый основной кадр, пока висит полноэкранный — плата запоминает его и покажет после.
- **Любое нажатие** закрывает экран и **не** запускает действие кнопки.
- Памяти хватает: основной кадр (48 КБ) хранится отдельно от буфера экрана (48 КБ).

| Экран | Кто рисует | Откуда вызывается | Длительность по умолчанию |
|---|---|---|---|
| **Wi-Fi QR** | Сервис | Действие кнопки, `tablo.show_qr` | 20 с, настраивается |
| **Сообщение** | Сервис | `tablo.show_message` | 30 с, настраивается |
| **Диагностика** | **Прошивка** | Долгое нажатие на 8 | 30 с |

- **Wi-Fi QR:** одна или несколько сетей рядом (для двух — по ~360×360 px), под каждой название. Строка вида `WIFI:T:WPA;S:<ssid>;P:<пароль>;;`. Сети задаются в HA (§8.3).
- **Сообщение:** заголовок, текст с переносами, необязательный значок MDI.
- **Диагностика:** IP, уровень Wi-Fi, время работы, версия прошивки, свободная память, связь с сервисом и HA, время последнего кадра. Рисует плата, потому что эта информация нужна как раз тогда, когда сервис не отвечает.

## 6. Сервис

### 6.1 Стек

- **Python 3.12, один процесс asyncio.**
- `aiohttp` — веб-сервер, WebSocket к плате, HTTP-клиент, WebSocket к HA. Одна библиотека на всё, чтобы не тянуть FastAPI + uvicorn + httpx.
- `Pillow` — вёрстка, без браузера.
- `icalendar`, `openpyxl`, `selectolax` (HTML t.me), `segno` (QR), стандартный `imaplib` в отдельном потоке.
- `anthropic` — подгружается лениво, только на время запроса.
- **SQLite** (`data/tablo.db`) — снимки оценок, кэш разметки таблиц, словарь переводов, просмотренные посты и письма, текущие новости и дедлайны.

### 6.2 Внутреннее устройство

```
источники ──▶ хранилище (SQLite + память) ──▶ модель экрана ──▶ рендер (Pillow) ──▶ кадр ──▶ плата
   ▲ расписание каждого                         (чистые данные)    1 бит, CRC
   └ события HA (мгновенно)
```

- **Источники** — независимые модули с интерфейсом «забери данные, верни типизированные записи». У каждого своё расписание, кэш и флаг «последний раз успешно». Ошибка одного не ломает остальные: блок показывает последние известные данные.
- **Модель экрана** — чистые данные без пикселей: «3 дедлайна», «прогноз на 8 часов», «плитка 3 включена». Её можно сравнивать и тестировать.
- **Рендер** превращает модель в картинку. Раскладка — координаты в одном файле.
- Изменилась модель → через 2 с рендер → если CRC другой, кадр уходит на плату.

### 6.3 Вёрстка

- Inter в чистом ч/б: сравним `fontmode="1"` и рендер в оттенках серого с порогом. Сначала на превью, окончательно — на живой панели.
- Текст, который не помещается, обрезается с «…».
- Значки погоды — свои, одной линией, как в макете: солнце, луна, облако, облако с 1–3 штрихами, снег, гроза, туман.
- **Значки кнопок — Material Design Icons** из файла шрифта MDI. Имя `mdi:lamp` переводится в символ шрифта по `meta.json`, размер 32 px. Это те же имена, что в HA.
- Срочный дедлайн выделен инверсией.

### 6.4 HTTP API

Для интеграции HA и отладки, на том же порту 8765. Запросы, меняющие состояние, требуют `Authorization: Bearer <api_token>`.

| Метод и путь | Что делает |
|---|---|
| `PUT /api/config` | Интеграция присылает полный конфиг (§8) |
| `POST /api/overlay/qr` | `{networks: [...], duration_s}` |
| `POST /api/overlay/message` | `{title, text, icon, duration_s}` |
| `POST /api/refresh` | `{full: bool, refetch: bool}` |
| `GET /api/status` | Состояние платы, источников, HA |
| `GET /frame.png` | Текущий кадр картинкой |
| `GET /emu` | Эмулятор (§9) |

### 6.5 Конфигурация

- **Секреты** — в `.env` сервиса: токен HA, ключ Anthropic, пароль приложения Яндекса, токены платы и API.
- **Содержательные настройки** (кнопки, ссылки, каналы, сроки) — в HA. Интеграция присылает их через `PUT /api/config`.
- Сервис хранит последний полученный конфиг на диске и работает по нему, даже если HA недоступен.
- Пока интеграции нет (этапы 1–6), тот же конфиг читается из `config.yaml`. Схема одна и та же.

### 7.1 Оценки — Google Sheets

**Доступ.** Все 4 таблицы открыты по ссылке. Сервис скачивает выгрузку `…/export?format=xlsx` без входа в Google. Если попадётся закрытая таблица, добавим OAuth от имени пользователя на чтение (`spreadsheets.readonly`). Приложение в Google Cloud тогда нужно перевести в *In production*, иначе токен сгорит через 7 дней.

**Настройки (в HA):** список таблиц `{url, label}` (label — короткое название курса для экрана: *Calc*, *DM*…), ФИО для поиска (`Пётр Сидоров`), окно новизны — **7 дней**.

**Алгоритм:**

1. Скачать таблицу, пройти по вкладкам. Найти **свою строку** по фамилии и началу имени (без учёта регистра, `ё` = `е`). Вкладки без своей строки пропускаются: старые, чужие потоки, статистика.
2. **Разметка вкладки** через Haiku. На вход — только верхние строки-шапки и своя строка, без чужих данных. На выход — JSON: какие столбцы — оценки, их подписи на английском, максимум (число или ячейка), столбец бонуса, или «пропустить вкладку». Разметка кэшируется по хэшу шапки и пересчитывается, только если шапка поменялась.
3. Достать значения, привести к **шкале 0–10**: `балл / максимум × 10`. Если максимум 10, значение берётся как есть.
4. Сравнить со снимком. Новое или изменившееся значение → запись в журнал с `first_seen`.
5. Нули до первой оценки считаются «не оценено» (в таблице 1 будущие даты заполнены нулями). Цена — настоящий ноль за работу не попадёт на экран. Это осознанный компромисс.
6. **Первый запуск** только запоминает снимок, без записей в журнал. Иначе в первый день на экран вывалилось бы всё.

**Правила для текущих таблиц** (Haiku должна прийти к тому же, это и есть тест):

| Таблица | Что берём | Пропускаем |
|---|---|---|
| 1 | Каждый столбец-дата во вкладке ДЗ → `HW Sep 17` | «ИТОГ», вкладку «Активность» |
| 2 | Семинар 1–7, Проект, СмартЛМС, Экзамен | — |
| 3 | **Каждая работа отдельно**: «Балл» во вкладках ДЗ-1А, 1Б…, итог во вкладках КР; переводим в 0–10 по максимуму из 2-й строки. Бонус «Балл\*» показываем отдельно: `+1` | Баллы по задачам, «Итоги», «Статистика», «old» |
| 4 | Столбцы «Оценка» после каждого квиза и ДЗ, «Доп листки» | Баллы по задачам №1…, «Средний балл» |

**Экран:** оценки с `first_seen` за последние 7 дней, сначала новые. Строка: `<label> <работа>` слева, оценка справа, например `DM HW 1A 8.4`, `Calc Quiz 2 6`, `DM HW 1B 9.5 +1`. Целые — без дробной части, остальные — один знак. Не помещаются → в заголовке блока счётчик `+2`. Новых нет → *no new grades*.

| **Telegram** (@example_se) | Haiku достаёт дедлайны при разборе постов (§7.5) | Учёба | `mdi:send` |
| **iCal** | События «Текущий рубежный контроль» → *Midterm* | Учёба | `mdi:calendar` |
| **HA (вручную)** | Пользователь добавляет сам в списке дел HA (§8.4) | Учёба или личное | `mdi:home-outline` |

**Значки категории:** учёба — `mdi:book-open-variant`, личное — `mdi:account`. Строка: `[категория][источник] Calc HW 5 … tomorrow`. Два значка по 14 px занимают около 34 px, на название остаётся примерно 20 символов. Если на панели будет тесно, значок категории можно убрать: у ручных личных дедлайнов источник и так HA.

**Список на экране:**
- Сначала предстоящие по сроку, срочный (сегодня или завтра) — инверсией. Ниже — **просроченные**: 3 дня после срока с пометкой `overdue`. Отмеченный выполненным (в the university app или в HA) пропадает сразу.
- Сколько помещается в блок (сейчас 5 строк по 22 px), остальное — счётчиком `+N` в заголовке.
- Дубли (тот же предмет, та же дата, похожее название) склеиваются, остаётся запись из более надёжного источника: the university app → iCal → почта → Telegram.

**Связь со списками дел HA** (§8.4): все дедлайны с экрана видны в HA двумя списками, «Tablo · Study» и «Tablo · Personal».
- Удалили или отметили выполненным пункт, пришедший из источника, — он скрывается с экрана и больше не возвращается, даже если источник пришлёт его снова. Так убираются ошибки Haiku.
- Добавили пункт со сроком — он появляется на экране с источником HA. Категория определяется списком, в который его добавили.
- **Разведка the university app — сделано (18.10).** Приложение декомпилировано (jadx), поток входа перехвачен (mitmproxy, эмулятор `tablo_hse`), вся цепочка проверена сквозным прогоном. Полная спецификация — [`research/hseapp/API.md`](research/hseapp/API.md). Pinning по факту не мешает ни mitmproxy, ни тем более сервису.
- **Авторизация сервиса:** клиент `app-oauth-client` (Keycloak на `sso.university.example`, без секрета). Храним `refresh_token`, обновляем `access_token` (3 ч) через `grant_type=refresh_token`; окно 21 день сдвигается при каждом обновлении, а сервис обновляет ежечасно — значит токен не протухает. Первый `refresh_token` сервис получает разовым входом (сейчас уже есть рабочий в `captures/`, gitignored).
- **Запрос дедлайнов:** `POST https://api.university.example/v2/deadlines` с `{"is_completed":false}` и `Bearer`. Берём `title`, `discipline` (обрезаем до « (» — «Дискретная математика (2026/2027 модули…)» → «Дискретная математика» — и переводим в английское название), `expires_at` (23:59 MSK). Пагинация `cursor` есть, но на практике одна страница.
- **Просроченные:** `is_completed:false` отдаёт и дедлайны со сроком в прошлом. Показываем их 3 дня после срока с пометкой `overdue` (см. выше).
- **Повторный вход**, если токен протух (сервис не обновлял его дольше 21 дня): HA присылает уведомление, в блоке Deadlines появляется *login needed*. Вход без эмулятора — через страницу сервиса: она даёт ссылку на страницу входа ВШЭ, вы входите в обычном браузере, браузер пытается открыть приложение и не может, а ссылку с кодом из адресной строки вставляете обратно на страницу сервиса. Сервис сам обменивает код на токен. Проверим на этапе 3.

### 7.3 Пары — iCal РУЗ

- Ссылка вида `https://api.university.example/v3/ruz/cal/<uuid>` (секретная, хранится в HA). Отдаёт около 5 недель (на 17.10: с 5.10 по 6.11), поддерживает ETag. Ограничение — 30 запросов за окно, нам с запасом хватает.
- Поля события: `SUMMARY` (предмет с «(рус)»), время, `LOCATION` (аудитория и адрес или ссылка MTS Link), `DESCRIPTION` (тип занятия и преподаватель).
- **Английские названия.** Словарь в SQLite: «Математический анализ» → *Calculus*, «Введение в программирование» → *Intro to Prog*. Новый предмет переводит Haiku один раз, любое название можно поправить в HA. «(рус)» убирается.
- **Аудитория:** первая часть `LOCATION` до запятой (`R609`), для ссылок — `online`.
- **Строка на экране:** `10:00 Algebra R401`. Время начала, предмет, аудитория.
- **Какие пары показывать:** 3 ближайшие ещё не закончившиеся сегодня. Сегодня больше нет — пары ближайшего учебного дня, в заголовке блока *tomorrow* или день недели.
- **Изменения** из почты и объявлений (§7.5) — пометка у пары: *moved*, *cancelled*, новая аудитория.

### 7.4 Погода — Open-Meteo

- Москва, `55.7558, 37.6173`, часовой пояс `Europe/Moscow`. Без ключа.
- `current`: температура, «ощущается как», код погоды, день или ночь. `hourly`: `temperature_2m`, `precipitation`, `precipitation_probability`, `weather_code`, `is_day`.
- Прогноз — 8 часов, начиная с текущего.
- Значок: сначала код погоды (снег, гроза, туман). Дождь рисуется, если вероятность ≥ 40%: < 2,5 мм/ч — 1 штрих, 2,5–7,6 — 2, > 7,6 — 3. Иначе облако, солнце или луна.

### 7.5 Новости — Telegram, почта и Haiku

**Сбор:**
- **Telegram** — веб-превью `https://t.me/s/<канал>`, около 20 последних постов, без аккаунта. Новые посты определяются по номеру в `data-post`. Каналы задаются в HA. Начальный список: @example_news3 (Рестарт), @example_news2 (Москвач), **@example_se (ПИ объявления — учебный)**, @example_news1.
- **Почта** — только `@edu.hse.ru` (Яндекс 360): `imap.yandex.ru:993`, пароль приложения, папка «Входящие», опрос раз в 5 мин, новые письма по UID. IMAP для этого ящика уже работает: пользователь подключал почту к другому приложению. Рабочая почта пока не подключается.

**Разбор (Haiku, модель `claude-haiku-5-5`):**
- На вход — новые посты и письма целиком (без HTML, цитат прошлой переписки и подписей, обрезка до ~8 000 символов), плюс текущий список новостей для склейки дублей.
- На выход — структурированный JSON по каждой записи:
  - `summary` — очень коротко, по-английски, 1–2 строки ширины колонки;
  - `importance` 1–5;
  - `source` — `tg` или `mail` (на экране значок);
  - `study` — учебная ли (почта `@edu.hse.ru` и @example_se — всегда да);
  - `deadlines[]` — найденные дедлайны: предмет, что, когда (→ §7.2, с пометкой);
  - `schedule_changes[]` — переносы и отмены пар (→ §7.3).
- **Когда запускать:** пришло учебное (письмо или пост @example_se) → в течение 5 мин; остальное — пачкой раз в час. Новых записей нет — Haiku не вызываем.

**Экран:** один общий список. Ранг = `importance`, учебным +1, при равенстве — новее выше. Новости стареют через 24 ч (настраивается). Слева от каждой — значок источника.

**Позже:** чтение чатов через Telethon (аккаунт пользователя). Отложено до готовности всей системы.

### 7.6 Дом — Home Assistant

- Сервис держит WebSocket к HA (`subscribe_entities`), состояния приходят мгновенно.
- Блок Home: температура и влажность (`sensor.room_sensor_temperature` / `_humidity`), «lights N of M», статус принтера.
- **«lights N of M»** считает 5 светильников с кнопок: потолок, лампа, стол, подсветка, шкаф. Список меняется в HA.
- **Принтер:** интеграции Klipper в HA сейчас нет. Ставим в HA интеграцию Moonraker и берём статус из её сущностей. Сервис отдельно в Moonraker не ходит.
- Тот же канал даёт состояния плиток (§8.2) и выполнение действий (`call_service`).

### 7.7 Вписывание текста в место

Цель — уместить как можно больше без «…». Дообучить Haiku нельзя, поэтому тот же эффект собираем из четырёх частей.

**1. Точный бюджет в запросе.** Сервис знает ширину каждого поля в пикселях и переводит её в символы по реальному шрифту (Inter Medium 16, в среднем 8,1 px на символ):

| Поле | Ширина | Бюджет |
|---|---|---|
| Строка новости | 230 px | 28 символов, 1–2 строки |
| Название дедлайна (справа «tomorrow») | 118 px | 15 символов |
| Подпись оценки (справа «9.5 +1») | 185 px | 23 символа |
| Предмет пары (справа аудитория) | 106 px | 13 символов |

Бюджеты пересчитываются из раскладки, а не задаются вручную: поменяли вёрстку — поменялся запрос.

**2. Варианты длины за один вызов.** Для каждой новости Haiku сразу возвращает `full` (до 2 строк) и `short` (1 строка). Укладчик идёт по рангу: самые важные — полностью, остальные — коротко, пока колонка не заполнится. Однострочная новость занимает 30 px, двухстрочная — 50 px, так что в колонку входит от 5 до 9 новостей вместо 5 обрезанных.

**3. Проверка настоящим рендером.** Каждый вариант меряется тем же шрифтом, что рисует экран. Не влез — один повторный запрос с точной причиной («34 символа, лимит 28»). «…» остаётся только последней страховкой.

**4. Стиль и примеры в запросе:** телеграфный английский без артиклей, цифры вместо слов, сокращения из общего словаря (HW, DM, Calc, Alg, Prog, Mon…Sun, Oct 21), символы `→ · &`, без названия источника в тексте (его показывает значок). Плюс 10–15 примеров «было → стало» из настоящих постов и писем.

**Где применяется:** новости; названия дедлайнов (из the university app приходит «Дедлайн ДЗ 3 по Дискретной Математике» → `DM HW 3`); подписи оценок; названия предметов (словарь из §7.3 с тем же бюджетом).

**Стоимость:** результат кэшируется по исходному посту или письму, Haiku видит каждую запись один раз.

**«Тренировка» — это набор проверок.** В `tests/fixtures` собираем 50+ настоящих постов из каналов и писем (без личных данных), а скрипт оценки прогоняет на них запрос и считает долю вписавшихся без «…» и среднюю длину. Запрос правим, пока доля не станет близкой к 100%.

## 8. Интеграция Home Assistant

Собственная интеграция `custom_components/tablo`. HA — единственное место, где пользователь что-то настраивает.

### 8.1 Связь

- **Интеграция → сервис:** HTTP API (§6.4) с `api_token`. При старте HA и любом изменении настроек интеграция шлёт полный конфиг.
- **Сервис → HA:** WebSocket API с долгоживущим токеном: состояния, `call_service`, а нажатия публикуются событием `tablo_button` (`button`, `press`).
- **Интеграция** слушает `tablo_button` и превращает его в триггеры устройства.

### 8.2 Кнопки 1–7

Настройки → Устройства → Tablo → «Настроить» → выбор кнопки. Для **короткого** и **долгого** нажатия отдельно:

| Поле | Варианты |
|---|---|
| Действие | Переключить сущность · Запустить скрипт или сцену · Показать Wi-Fi QR (сети, длительность) · Показать сообщение · Только событие |
| Сущность | Выбор из списка HA |
| Значок (у кнопки один) | Стандартный выбор значков HA (`mdi:*`). Пусто — значок сущности |
| Подсветка плитки (у кнопки одна) | По умолчанию — состояние той же сущности. Можно другую сущность или «никогда» |

- Изменения появляются на экране сразу.
- **Триггеры устройства** «Tablo: кнопка N, короткое / долгое» — для любых автоматизаций. Срабатывают при любом настроенном действии, включая «только событие». Кнопка 8 тоже публикует события.

**Начальные назначения** (пользователь меняет в HA):

| # | Значок | Короткое | Долгое |
|---|---|---|---|
| 1 | `mdi:power` | Скрипт «выключить весь свет» (создать в HA) | «Ухожу»: свет и VPN-точка |
| 2 | `mdi:ceiling-light` | `light.ceiling_light` | Соло: только этот свет |
| 3 | `mdi:lamp` | `light.desk_lamp` | Яркость по кругу 100 → 40 → 10% |
| 4 | `mdi:desk` | `light.desk_light` | Соло |
| 5 | `mdi:led-strip-variant` | `light.desk_backlight` (Tuya, RGB-лента 1 м, не адресная) | Цвет или яркость по кругу |
| 6 | `mdi:hanger` | `light.closet_light` | Включить и выключить через 5 мин |
| 7 | `mdi:wifi` | `switch.vpn_ap` | Wi-Fi QR: основная сеть + VPN, 20 с |
| 8 | `mdi:refresh` | *прошито*: полное обновление | *прошито*: диагностика 30 с |

«Соло», «яркость по кругу» и таймер — это скрипты HA. Шаблоны для них положим в репозиторий.

### 8.3 Остальные настройки

- **Wi-Fi сети** для QR: название, пароль, тип защиты, скрытая ли.
- **Источники:** ссылка iCal, таблицы `{url, label}`, ФИО, окно новизны оценок, Telegram-каналы, срок жизни новостей, словарь английских названий предметов.
- **Дом:** датчик температуры и влажности, список светильников для «lights N of M», сущность принтера.
- **Экран:** `semester_start`, время ночного полного обновления.

### 8.4 Действия и сущности

| Действие | Параметры |
|---|---|
| `tablo.show_qr` | `networks`, `duration` (20 с) |
| `tablo.show_message` | `title`, `text`, `icon`, `duration` (30 с) |
| `tablo.full_refresh` | — |
| `tablo.refresh_data` | `sources` (необязательно) |

Сущности: `binary_sensor` «подключено», `sensor` уровень Wi-Fi, `sensor` время последней связи.

**Списки дел** (`todo`): «Tablo · Study» и «Tablo · Personal» — все дедлайны с экрана, со сроками. Удаление или отметка «выполнено» скрывает дедлайн, новый пункт со сроком добавляет свой дедлайн (§7.2). Списки открываются в приложении HA на телефоне.

## 9. Эмулятор

Страница `http://<сервис>:8765/emu`, которая повторяет логику прошивки на JavaScript.

- Подключается по **тому же протоколу**, что и плата. Сервис не отличает её от железа.
- Холст 800×480, масштаб 1× или 2×, цвета «под бумагу».
- Сама рисует часы, дату и строку статуса по зонам из `config`, в часовом поясе из `config`.
- **Кнопки:** 8 кнопок под экраном. Клик — короткое нажатие, удержание ≥ 600 мс — долгое, клавиши `1`–`8`. Мгновенная инверсия плиток, откат по `button_result`, полноэкранные экраны с `ttl`, своя диагностика на 8-й.
- **Отладка:** подсветка прямоугольников частичного обновления, переключатель «сервис недоступен» (рвёт соединение), журнал сообщений протокола.
- Работает в браузере на Маке и памяти сервера не занимает.

## 10. Прошивка

Пишется, когда приедет железо. Здесь — то, что важно для протокола.

- PlatformIO + Arduino, `GxEPD2_750_GDEY075T7` (быстрое частичное обновление), `arduinoWebSockets`, `ArduinoJson`.
- Время — NTP, пояс `MSK-3`. Шрифты Inter 64 px (цифры) и 16 px в формате Adafruit GFX, значки статуса — битмапы.
- Память: основной кадр 48 КБ + буфер экрана 48 КБ. У ESP32-WROOM без PSRAM помещается вместе с Wi-Fi.
- 8 кнопок на GPIO. Какие пины свободны после SPI экрана — проверим на плате: 34–39 только на вход и без подтяжки, strapping-пины не трогаем.
- Wi-Fi, адрес сервиса и токен — в `secrets.h`. Обновление по воздуху (ArduinoOTA). USB-C платы выведен наружу, так что прошить можно и без разборки.

## 12. Развёртывание и ресурсы

**Разработка** — на Маке, сервис ходит в настоящий HA на `192.168.1.50:8123`.

**Боевой запуск** — Docker Compose на `server`:
- Сеть bridge, порт открыт только на LAN-адресе хоста, DNS задан явно (`dns:`). Не `network_mode: host`: при нём контейнер берёт DNS хоста, а HA однажды уже ломался из-за этого.
- HA доступен по `192.168.1.50:8123`.
- Том `./data` для SQLite и сохранённого конфига.
- `mem_limit: 256m`.

**Бюджет памяти** (оценка, проверим замером):

| Состояние | RSS |
|---|---|
| Ожидание | 80–120 МБ |
| Рендер кадра | +10–20 МБ на пике |
| Разбор таблицы на 2,4 МБ (openpyxl, read-only) | +20–40 МБ на пике |

CPU в ожидании около нуля. Если понадобится меньше — `anthropic` и Google-часть грузятся только на время запроса.

## 16. Открытые вопросы

Решены 18.10: просроченные дедлайны, скрытие ошибочных и свои дедлайны, повторный вход в the university app, «lights N of M», подсветка, принтер, IMAP почты — ответы внесены в §7.2, §7.5, §7.6, §8.2, §8.4.

Осталось, решается по ходу:

1. **Маршруты** до внешних сервисов — решим на этапе развёртывания.
2. **Стоимость Haiku:** посчитаем после недели работы, по реальному объёму постов и писем.
3. **Полное обновление:** как часто на самом деле нужно. Подберём на живой панели.
4. **Шрифт в ч/б:** без сглаживания или с порогом. Решим на превью и на панели.
5. **Повторный вход в the university app через браузер:** страница `/hseapp` готова, страница входа ВШЭ принимает адрес возврата приложения. Осталось один раз пройти вход вручную и проверить, где браузер показывает адрес `ru.hse.hseappx://…` с кодом (консоль Chrome или адресная строка).
